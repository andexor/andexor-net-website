# Implementation Plan: Cookies Page

**Branch**: `87-implement-cookiebot` | **Date**: 2026-10-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/078-cookies-page/spec.md`

## Summary

Move Cookiebot's Cookie Declaration from the footer to its own Markdown page, `content/cookies.md` at `/cookies`. The
page holds a marker line, `<!-- cookie-declaration -->`. A small remark plugin in `src/lib/content.ts` turns that one
line into the declaration's script element (an element built from the syntax tree, so raw HTML is still dropped from
Markdown). The page body is already rendered with `dangerouslySetInnerHTML` and `data-raw-html=""`, so React does not
hydrate it and the nodes Cookiebot adds next to the script cannot cause a hydration mismatch (the reasoning of spec 077,
unchanged). The footer loses its declaration container and gains a "Cookies" link in the Company column. The sitemap is
regenerated.

## Technical Context

**Language/Version**: TypeScript on Bun; Next.js static export (`output: "export"`)

**Primary Dependencies**: none added (`unified`, `remark`, `rehype` are already used in `src/lib/content.ts`)

**Storage**: N/A

**Testing**: vitest for the plugin; Playwright e2e against `out/` for the page, footer, and phone width (Cookiebot
stubbed through `tests/e2e/fixtures.ts`)

**Target Platform**: Cloudflare Workers static assets; local Docker via `server.ts`

**Project Type**: Static web site

**Performance Goals**: no cost beyond Cookiebot's own file on `/cookies`; other pages lose a request (SC-001)

**Constraints**: hydration on every load (FR-006); no sideways scrolling (FR-007); no other raw HTML allowed in
Markdown (FR-003); formatter and DOM gate must pass; straight quotes; no link underline

**Scale/Scope**: one plugin, one content file, one footer edit, test changes, notes in `CLAUDE.md` and
`content/README.md`

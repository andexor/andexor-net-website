# Feature Specification: Sitemap

**Feature Branch**: `79-sitemap`

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "Review the files in the content folder and create a sitemap.xml file. Place it in the
content folder."

Follows spec 002 (Markdown content pages, where each `.md` file in `content/` is a page at its path).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Search engines can find every page (Priority: P1)

A search engine reads the sitemap and learns the address of the home page and of every published content page.

**Why this priority**: Content pages are not linked from the home page or footer yet, so a crawler has no other way to
find them.

**Independent Test**: Open `content/sitemap.xml` and compare its addresses with the `.md` files in `content/`.

**Acceptance Scenarios**:

1. **Given** the files in `content/`, **When** the sitemap is read, **Then** it lists `https://andexor.net/` and one
   address per published page, such as `https://andexor.net/web-hosting` for `content/web-hosting.md`.
2. **Given** `content/README.md` and any page with `draft: true`, **When** the sitemap is read, **Then** neither is
   listed.
3. **Given** each listed page, **When** its entry is read, **Then** `lastmod` is the date of the page file's last
   change.

---

### User Story 2 - The sitemap is served (Priority: P1)

A crawler requests `/sitemap.xml` and receives the file.

**Independent Test**: Run `bun run build`, serve `out/`, and request `/sitemap.xml`.

**Acceptance Scenarios**:

1. **Given** a finished build, **When** `/sitemap.xml` is requested, **Then** the response is 200 with the contents of
   `content/sitemap.xml`.

## Requirements *(mandatory)*

- **FR-001**: The sitemap is `content/sitemap.xml`, in the Sitemaps 0.9 format, generated by `scripts/generate-sitemap.ts`.
- **FR-002**: Addresses use `https://andexor.net` with no trailing slash, matching the routes the site builds.
- **FR-003**: `build.sh` runs `bun scripts/generate-sitemap.ts` (also `bun run sitemap`) before the Docker build. It
  rewrites the file from the published pages (`listContentSlugs`), so added, removed, and drafted pages are picked up.
  Each `lastmod` is the date of the page file's last git commit, or today when the file has uncommitted changes. It
  runs on the host because the image build has no `.git` directory. The regenerated file is committed with the change.
- **FR-004**: `bun run build` copies `content/sitemap.xml` and `content/robots.txt` to the root of `out/` after `next build`
  (`scripts/copy-crawler-files.ts`), so the static server serves them at `/sitemap.xml` and `/robots.txt`. The build
  fails if either file is missing. `robots.txt` is written by hand and points to the sitemap.
- **FR-005**: No test is written for the sitemap's contents.
